# Google OAuth Setup for Travel Agent

## Overview

Travel Agent uses two Google authentication flows:

### 1. API Flow — `POST /api/v1/oauth/google`

Frontend sends a Google ID token, backend verifies it and returns JWT. Used for mobile/SPA clients.

**Route:** `config/routes.rb` line 107:
```ruby
post "/oauth/google", to: "oauth#google"
```

**Gem required:** `googleauth` (server-side ID token verification only, no omniauth-google-oauth2 needed)

**Credentials needed:** Only `client_id` (for `Google::Auth::IDTokens.verify_oidc`)

**Controller:** `app/controllers/api/v1/oauth_controller.rb`

Request:
```json
POST /api/v1/oauth/google
Content-Type: application/json

{
  "credential": "eyJhbGciOiJSUzI1NiIs...",
  "role": "user"  // optional: "user" or "affiliator", defaults to "user"
}
```

Success response (201):
```json
{
  "user": { "id": 1, "name": "...", "email": "...", "role": "user" },
  "token": "eyJ..."
}
```

### 2. Web Flow — `GET /users/auth/google_oauth2`

Traditional OAuth2 redirect flow through Devise + OmniAuth for browser-based login.

**Gem required:** `omniauth-google-oauth2` (NOT in Gemfile yet — must be added)

**Credentials needed:** Both `client_id` and `client_secret`

**Routes (auto-generated by Devise):**
| Method | Path | Controller |
|--------|------|-----------|
| GET/POST | `/users/auth/google_oauth2` | `devise/omniauth_callbacks#passthru` |
| GET/POST | `/users/auth/google_oauth2/callback` | `devise/omniauth_callbacks#google_oauth2` |

## Credentials Location

Store in Rails encrypted credentials:
```yaml
google:
  client_id: "xxxxx.apps.googleusercontent.com"
  client_secret: "GOCSPX-xxxxx"
```

## User Model (`app/models/user.rb`)

Key OAuth fields added via migration:
- `provider` (string) — e.g. "google"
- `uid` (string) — Google user ID (`sub` from token)
- Unique partial index on `[provider, uid]`

Devise modules:
```ruby
devise :omniauthable, omniauth_providers: [:google_oauth2]
```

`User.from_google_oauth` logic:
1. Find by `provider="google"` + `uid` → existing OAuth user, login
2. Find by email → link existing account (set provider + uid)
3. Create new user with random password (OAuth users don't need passwords)

## Debugging "Invalid Google token" / "Token not verified" Errors

When the endpoint returns `{"error":"Invalid Google token"}` (401), check the production logs first:

```bash
ssh <host> "docker logs <container> --tail 100 2>&1 | grep -i google"
```

### Most Common Cause: Frontend sends access token instead of ID token

Google's OAuth response contains two distinct tokens:

| Token type | Prefix | Purpose | Used by backend? |
|-----------|--------|---------|------------------|
| **ID token** (`credential`) | `eyJ...` (JWT) | Authentication — proves who the user is | ✅ `Google::Auth::IDTokens.verify_oidc` |
| **Access token** (`access_token`) | `ya29.` | Authorization — calls Google APIs on user's behalf | ❌ Cannot be verified by IDTokens |

**Symptom in logs:**
```
Google ID token verification failed: Token not verified as issued by Google
Parameters: {"credential" => "ya29.a0AQvPy..."}
```

The `ya29.` prefix is the giveaway — it's an access token, not an ID token.

**Fix in frontend — use `response.credential`, NOT `response.access_token`:**

```javascript
// ❌ WRONG — this is what causes the error
google.accounts.id.initialize({
  client_id: GOOGLE_CLIENT_ID,
  callback: (response) => {
    fetch("/api/v1/oauth/google", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        credential: response.access_token  // sends access token → fails!
      })
    })
  }
})

// ✅ CORRECT
google.accounts.id.initialize({
  client_id: GOOGLE_CLIENT_ID,
  callback: (response) => {
    fetch("/api/v1/oauth/google", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        credential: response.credential  // sends ID token (JWT) → works!
      })
    })
  }
})
```

### Variant: OAuth 2.0 Token Endpoint Response (server-side flow)

If the frontend uses the **authorization code flow** (GIS `response.code` → server exchanges at `https://oauth2.googleapis.com/token`), the token endpoint returns a JSON object with both tokens:

```json
{
  "token_type": "Bearer",
  "access_token": "ya29.a0...",
  "scope": "email profile openid ...",
  "expires_in": 3599,
  "id_token": "eyJhbGciOiJSUzI1NiIs...",
  "session_state": { "extraQueryParams": { "authuser": "0" } }
}
```

In this flow, the GIS callback gives you `response.code` (NOT `response.credential`). You exchange `response.code` server-side for tokens, then extract `id_token` from the response and forward it to the backend:

```javascript
// Token exchange happens server-side — then forward to backend API
const tokenResponse = await fetch("https://oauth2.googleapis.com/token", { ... })
const data = await tokenResponse.json()

// ✅ Extract id_token from OAuth token response and send as credential
fetch("/api/v1/oauth/google", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ credential: data.id_token })
})

// ❌ DON'T send data.access_token — it's an OAuth API token, not an identity JWT
// ❌ DON'T send the whole JSON object — backend expects just the ID token string
```

**Key distinction:**
| Flow | GIS callback gives | What to send as `credential` param |
|------|-------------------|-------------------------------------|
| Implicit (popup) | `response.credential` (ID token JWT string) | `response.credential` directly |
| Authorization code | `response.code` (one-time code) | Exchanged server-side → use `id_token` from token response |

### Other causes

| Log message | Cause | Fix |
|------------|-------|-----|
| `GOOGLE_CLIENT_ID not configured` | Credentials not readable or env var not set | Check `RAILS_MASTER_KEY` in `.kamal/secrets`, verify `credentials.yml.enc` has `google.client_id` |
| `Token not verified as issued by Google` + token starts with `eyJ` | Token expired (ID tokens valid 1 hour) or wrong audience (`aud` doesn't match `client_id`) | Frontend must use matching Google Client ID; token must be fresh |
| `Token not verified as issued by Google` + token starts with `ya29.` | **Frontend sent access token instead of ID token** | See fix above — this is the most common mistake |

## Production Checklist

1. **`master.key`** must be on the server (or set `RAILS_MASTER_KEY` env var)
2. **Google Cloud Console**: For API flow (ID token), no redirect URI needed. Web flow is intentionally not configured for Travel Agent — only `POST /api/v1/oauth/google` is used.
3. **Add `omniauth-google-oauth2` gem** only if web flow is needed (not needed for API-only flow)
4. **Configure Devise** web flow in `config/initializers/devise.rb` only if web flow is needed:
   ```ruby
   config.omniauth :google_oauth2,
     Rails.application.credentials.dig(:google, :client_id),
     Rails.application.credentials.dig(:google, :client_secret)
   ```
