# Finance Couple — DB Schema (PostgreSQL)

Database: `cozyfinance` on `127.0.0.1:5432`

## Tables

### transactions
| Column | Type | Notes |
|--------|------|-------|
| id | UUID | Primary key, generated by Python (`uuid.uuid4()`) |
| type | TEXT | `"expense"`, `"income"`, or `"transfer"` |
| amount | INTEGER | In rupiah (e.g., 200000) |
| description | TEXT | Transaction description |
| category | TEXT | e.g., "makanan", "gaji", "transfer keluar", "transfer masuk" |
| wallet_id | UUID | FK → wallets.id |
| wallet_name | TEXT | Denormalized for easy display |
| wallet_detail_id | UUID | Nullable, FK → wallet details |
| wallet_detail_name | TEXT | Nullable |
| created_by | TEXT | `"suami"` or `"istri"` |
| created_by_name | TEXT | `"Suami"` or `"Istri"` |
| date | DATE | Transaction date (indexed) |
| created_at | TIMESTAMPTZ | Auto |
| attachments | JSONB | Array of attachment objects |

### wallets
| Column | Type | Notes |
|--------|------|-------|
| id | UUID | Primary key |
| name | TEXT | e.g., "BCA Suami" |
| type | TEXT | `"bank"`, `"ewallet"`, or `"cash"` |
| owner | TEXT | `"suami"`, `"istri"`, or `"joint"` |
| balance | INTEGER | Denormalized running total |
| icon | TEXT | Emoji, e.g., "🏦" |
| color | TEXT | Hex color |
| details | JSONB | Array of `{id, name, balance}` objects |
| created_at | TIMESTAMPTZ | Auto |

### categories
| Column | Type | Notes |
|--------|------|-------|
| type | TEXT | `"expense"` or `"income"` |
| name | TEXT | Category name |
| exclude_from_report | BOOLEAN | Whether to exclude from monthly summaries |
| (composite PK) | | (type, name) |

## Key Relationships
- `transactions.wallet_id` → `wallets.id`
- `transactions.wallet_detail_id` → `wallets.details[].id` (JSONB field, not a real FK)
- `categories` has composite PK on (type, name)

## Transfer Convention
- Transfer creates 2 rows in `transactions`, both with `type = 'transfer'`
- Source wallet: `category = 'transfer keluar'` → balance decreases
- Destination wallet: `category = 'transfer masuk'` → balance increases
- Both rows have same `amount`, `description`, `date`, `created_by`, `created_by_name`

## Balance Integrity
- `wallets.balance` is denormalized — must be kept in sync by:
  - `add_transaction`: delta += amount (income/transfer masuk) or -= amount (expense/transfer keluar)
  - `delete_transaction`: revert the delta
  - `transfer_between_wallets`: atomic update of both source and destination
- Frontend has `recalculateAllBalance` in Settings as fallback
